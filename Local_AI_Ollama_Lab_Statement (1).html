import time, json

def generate(prompt, model=None, system=None, fmt=None, images=None, options=None, think=None):
    """Call Ollama /api/generate (non-streaming) and return the full JSON dict
    plus the measured wall-clock time under the key 'wall_s'."""
    payload = {"model": model or MODEL, "prompt": prompt, "stream": False}
    if system:  payload["system"] = system
    if fmt:     payload["format"] = fmt          # "json" or a JSON schema
    if images:  payload["images"] = images       # list of base64 strings
    if options: payload["options"] = options
    if think is not None: payload["think"] = think  # False disables 'thinking' on reasoning models
    t0 = time.perf_counter()
    r = requests.post(f"{OLLAMA}/api/generate", json=payload, timeout=600)
    r.raise_for_status()
    out = r.json()
    out["wall_s"] = time.perf_counter() - t0
    return out

def ask(prompt, **kw):
    """Shortcut: return only the text, and print timing."""
    out = generate(prompt, **kw)
    print(f"[{out['wall_s']:.1f}s]")
    return out["response"]

### 1. Definition
A Directed Acyclic Graph (DAG) is a directed graph that has no directed cycles. This means that there is no way to start at any vertex (node) and follow a set of edges that will eventually loop back to the starting vertex. In a DAG, the edges have a direction, indicating a one-way relationship between the nodes.

### 2. Example
Imagine a course schedule in a university. You might have a set of courses where certain courses must be completed before others can be taken. For example, you might need to complete Calculus I before you can take Calculus II. If we represent each course as a node and the prerequisite relationship as a directed edge, we would have a DAG.

A simple example could be:
- Node A: Calculus I
- Node B: Calculus II
- Node C: Linear Algebra

The edges could be:
- A → B (Calculus I is a prerequisite for Calculus II)
- A → C (Calculus I is a prerequisite for Linear Algebra)

### 3. Adjacency Matrix
An adjacency matrix is a way to represent a graph using a two-dimensional matrix where the rows and columns correspond to the nodes of the graph. For a directed graph, the value in the matrix at position (i, j) is 1 if there is a directed edge from node i to node j, and 0 otherwise. In the context of a DAG, the adjacency matrix will have 0s on the diagonal if the graph is acyclic, and 1s only for edges that exist in the graph.

For the example above, the adjacency matrix could look like:
```
   A   B   C
A  0   1   1
B  0   0   0
C  0   0   0
```

### 4. Real-world Application
DAGs have numerous real-world applications. Some common examples include:
- **Dependency resolution**: In software package management, dependencies between packages can be represented as a DAG to ensure that dependencies are resolved correctly.
- **Task scheduling**: In project management, tasks that have dependencies on other tasks can be represented as a DAG to determine the order in which tasks should be executed.
- **Rendering in computer graphics**: In rendering pipelines, the dependencies between different stages of the rendering process can be modeled using a DAG to optimize the rendering process.

Recursion in Python is a method where the solution to a problem depends on solutions to smaller instances of the same problem. In programming, a recursive function is a function that calls itself during its execution. The key aspects of recursion include:

1. **Base Case**: This is the condition that stops the recursion. Without a base case, a recursive function would continue to call itself indefinitely, potentially leading to a stack overflow error.

2. **Recursive Case**: This is the part of the function that breaks the problem into smaller subproblems and calls the function itself.

Here's a simple example of a recursive function in Python that calculates the factorial of a number:

```python
def factorial(n):
    # Base case
    if n == 0 or n == 1:
        return 1
    # Recursive case
    else:
        return n * factorial(n - 1)

# Example usage
print(factorial(5))  # Output should be 120
```

```python
def sum_of_numbers(n):
    # Base case
    if n == 1:
        return 1
    # Recursive case
    else:
        return n + sum_of_numbers(n - 1)

# Example usage
print(sum_of_numbers(5))  # Output should be 15
```

### Important Considerations

1. **Recursion Limit**: Python has a limit on the depth of recursion to prevent infinite recursion, which can lead to a `RecursionError`. You can check this limit using `sys.getrecursionlimit()` and increase it if necessary, but be cautious as deep recursion can consume a lot of memory and stack space.

2. **Performance**: Recursive functions can be less efficient than iterative ones due to the overhead of function calls. This is especially true for deep recursion, which can lead to stack overflow errors.

3. **Tail Recursion**: Some languages optimize tail recursion, meaning the recursive call is the last operation in the function. Python does not optimize tail recursion, so deep recursion can be problematic.

### When to Use Recursion

- When the problem naturally splits into smaller subproblems.
- When the base case and recursive case are clearly defined.
- For problems where recursion leads to cleaner, more understandable code.

In summary, recursion in Python involves defining a function that calls itself to solve a smaller instance of the same problem, with a clear stopping condition. Proper use of recursion can lead to elegant solutions but must be used with care to avoid issues like infinite recursion and stack overflow.

"""Mini-RAG: a tiny local retriever + prompt builder (keyword TF-IDF, no extra libraries)."""
import math, os, re
from collections import Counter

STOPWORDS = set("""a an the of to in on and or is are was were be by for with as at from that this
it its what which who how why when where do does did can could should would about into using use
learn learns through between such""".split())


def tokenize(text):
    return [w for w in re.findall(r"[a-zA-Z]+", text.lower()) if w not in STOPWORDS]


def load_documents(folder="documents"):
    docs = {}
    for fn in sorted(os.listdir(folder)):
        if fn.endswith(".txt"):
            with open(os.path.join(folder, fn), encoding="utf-8") as f:
                docs[fn] = f.read()
    return docs


class Retriever:
    def __init__(self, docs):
        self.docs = docs
        self.tokens = {n: Counter(tokenize(t)) for n, t in docs.items()}
        df = Counter(w for c in self.tokens.values() for w in c)
        N = len(docs)
        self.idf = {w: math.log((N + 1) / (d + 0.5)) for w, d in df.items()}

    def score(self, question):
        q = tokenize(question)
        return {
            name: sum(self.idf.get(w, 0) * (1 + math.log(c[w])) for w in set(q) if c[w] > 0)
            for name, c in self.tokens.items()
        }

    def top(self, question, k=1, min_score=0.01):
        ranked = sorted(self.score(question).items(), key=lambda x: -x[1])
        return [(n, s) for n, s in ranked[:k] if s >= min_score]

    def context(self, question, k=1):
        hits = self.top(question, k)
        return hits, "\n\n".join(f"[{n}]\n{self.docs[n]}" for n, _ in hits)


def build_prompt(question, context):
    return f"""Answer the question using only the CONTEXT below.
If the answer is not contained in the context, say: "Information not available."

CONTEXT:
{context if context else '(no relevant document found)'}

QUESTION:
{question}
"""

"""Benchmark local Ollama models on the same prompt."""
import time, requests, psutil, pandas as pd

OLLAMA = "http://localhost:11434"
PROMPT = "Write a 500-word explanation of reinforcement learning."


def unload(model):
    requests.post(f"{OLLAMA}/api/generate", json={"model": model, "keep_alive": 0})
    time.sleep(2)


def loaded_info(model):
    for m in requests.get(f"{OLLAMA}/api/ps").json()["models"]:
        if m["name"].startswith(model.split(":")[0]):
            return m["size"] / 1e9, m.get("size_vram", 0) / 1e9
    return float("nan"), float("nan")


def bench(model, prompt=PROMPT, runs=1):
    rows = []
    for _ in range(runs):
        unload(model)                       # cold start, so the load time is visible
        t0 = time.perf_counter()
        r = requests.post(f"{OLLAMA}/api/generate",
                          json={"model": model, "prompt": prompt, "stream": False,
                                "think": False}, timeout=900).json()
        wall = time.perf_counter() - t0
        total_gb, vram_gb = loaded_info(model)
        rows.append({
            "Model": model,
            "Disk size (GB)": next((m["size"] / 1e9 for m in requests.get(f"{OLLAMA}/api/tags").json()["models"]
                                    if m["name"].startswith(model.split(":")[0])), float("nan")),
            "Loaded size (GB)": total_gb,
            "VRAM (GB)": vram_gb,
            "Load time (s)": r.get("load_duration", 0) / 1e9,
            "Response time (s)": wall,
            "Tokens": r.get("eval_count"),
            "Tokens/s": r["eval_count"] / (r["eval_duration"] / 1e9),
            "System RAM used (%)": psutil.virtual_memory().percent,
        })
    return pd.DataFrame(rows)


if __name__ == "__main__":
    import sys

               + [{"role": "user", "content": user_msg}]

    t0 = time.perf_counter()
    try:
        out = call_ollama(messages, structured)
    except requests.RequestException as e:
        return jsonify(error=f"Ollama error: {e}"), 502
    elapsed = time.perf_counter() - t0

    answer = out["message"]["content"]
    # store the plain question (not the long context) to keep history small
    history.append({"role": "user", "content": question})
    history.append({"role": "assistant", "content": answer})

    parsed = None
    if structured:
        try:
            parsed = json.loads(answer)
        except json.JSONDecodeError:
            pass

    tokens = out.get("eval_count")
    tps = tokens / (out["eval_duration"] / 1e9) if tokens and out.get("eval_duration") else None
    return jsonify(answer=answer, structured=parsed,
                   sources=[{"doc": n, "score": round(s, 2)} for n, s in hits],
                   seconds=round(elapsed, 2), tokens=tokens,
                   tokens_per_s=round(tps, 1) if tps else None)


@app.route("/reset", methods=["POST"])
def reset():
    history.clear()
    return jsonify(ok=True)

<h2 id="Part-18-%E2%80%94-Questions-for-the-Report">Part 18 — Questions for the Report¶</h2><p>Answer each question in your own words (use your measurements from Parts 6 and 16 for Q13–Q14).</p> <p>Q1. What is Local AI?</p> <p>**Local AI refers to running artificial intelligence models directly on a user's personal device (computer, laptop, or smartphone) rather than relying on a remote cloud server. The data, computation, and model weights remain entirely on the local hardware. **</p> <p>Q2. Difference between a Cloud LLM and a Local LLM?</p> <p>**A Cloud LLM (like ChatGPT) runs on massive data centers. It requires an internet connection, sends your data to a third party, and usually charges per token, but offers state-of-the-art performance. A Local LLM runs on your own hardware (CPU/GPU). It guarantees 100% privacy, works offline, and is free to use, but is limited by your computer's RAM and processing speed. ** Q3. What role does Ollama play?</p> <p>**Ollama acts as a local server and model manager. It downloads the models, optimizes them for your hardware (handling the GPU/CPU split), and exposes them via a REST API on localhost:11434. This allows any application (Python, Web apps) to easily communicate with the local LLM. **</p> <p>Q4. What is model quantization?</p> <p>**Quantization is a compression technique that reduces the size of the model. Instead of storing every weight (parameter) with 16-bit or 32-bit precision, it stores them using 4-bit or 8-bit precision (e.g., Q4_K_M seen in ollama show). This drastically reduces the RAM required to run the model, with a very small loss in accuracy. **</p> <p>Q5. Why does model size affect memory consumption?</p> <p>**A model's size (e.g., 7B parameters) determines how much RAM/VRAM is needed. Each parameter must be loaded into memory. A 7B model at 4-bit quantization requires about 4.7 GB of RAM just to load the weights, whereas a 2B model requires only 1.6 GB. Larger models need more memory to perform the mathematical operations. **</p> <p>Q6. Why can a smaller model sometimes be preferable?</p> <p>**As demonstrated in my benchmark (Part 16), a smaller model like gemma2:2b is dramatically faster (111 tokens/s) and uses less than half the memory of a 7B model. A smaller model is preferable when:</p> <p>The hardware is limited (e.g., a standard laptop with 8 GB of RAM).</p> <p>Low latency is critical (e.g., real-time chatbots, autocomplete).</p> <p>The task is simple (e.g., basic text classification or short summarization), where the advanced reasoning of a larger model isn't necessary. ** Q7. Advantages of local inference?</p> <p>**Absolute Privacy: No data is sent to a third-party cloud. This is crucial for handling sensitive information (medical, legal, corporate data).</p> <p>Offline Operation: Works perfectly without an internet connection.</p> <p>Zero Marginal Cost: No API fees or subscription limits. You can generate millions of tokens for free (only paying for electricity).</p> <p>Full Control: You own the model and the data pipeline. **</p> <p>Q8. Disadvantages of local inference?</p> <p>Hardware Constraints: Requires significant RAM/VRAM and a decent CPU/GPU. You cannot run massive 70B+ models on a standard computer.</p> <p>Lower Capability: Even the best 7B model is generally less "smart" than cloud giants like GPT-4 or Claude 3.5.</p> <p>Maintenance: The user is responsible for downloading models, managing storage space, and updating the Ollama server.</p> <p>Speed: Can be slower than cloud data centers if you don't have a dedicated high-end GPU.</p> <p>Q9. It allows our Python code to interact with the complex C++ inference engine of Ollama using simple HTTP requests. By sending a JSON payload with parameters (model, prompt, stream) to endpoints like /api/generate or /api/chat, the application receives a structured JSON response with the generated text and performance metrics (eval_count, eval_duration). This decouples the UI from the AI engine.</p> <p>Q11. What is RAG?</p> <p>RAG stands for Retrieval-Augmented Generation. It is an architectural pattern that enhances the accuracy and reliability of LLMs. Instead of relying solely on the model's internal training data (which can lead to hallucinations), a RAG system first retrieves relevant documents from a local knowledge base (using a retriever like TF-IDF or vector search). It then injects this retrieved context into the prompt sent to the LLM. The LLM is instructed to answer using only this context. As demonstrated in Part 13, this ensures the AI answers based on specific, up-to-date, or private documents without needing to be retrained.</p> <p>Q12. A multimodal LLM (like LLaVA or GPT-4V) is trained on multiple data types (modalities) simultaneously—typically text and images.
